# Tests

Stubs marked `// Filled by #N` belong to that issue. Tests live in `src/gametest/.../test/`:

- Add test classes and evidence scenarios to the stubs that already exist. `gradle/gametest.gradle.kts` generates the gametest `fabric.mod.json` entrypoint lists from the classes (an `@GameTest` method, `implements FabricClientGameTest`, or `extends EvidenceScenario`) and fails the build for a `*Test` or `*Scenario` class it cannot register; never edit a list. The lists are sorted by name, and no test may depend on that order. A test that swaps a world-global saved record (colony, hangar, repair state, serials) does it through `WorldData.with` or `WorldData.swap` (`test/support`), which set, run the body and restore in a `finally` on the same tick; a direct `getDataStorage().set(` in `src/gametest` fails the build. `WorldDataGuard` stops the server GameTest run if a swap lives into the next tick. `./gradlew runGameTest -PgametestOrder=reverse` runs the server suite in reverse name order to catch a leak. A server stub is `<Thing>Test`, a client stub `<Thing>ClientTest`, a scenario `evidence/<Thing>Scenario` named `m2-<thing>`. A scenario stub throws "stub: #N fills it" when it is selected, and does nothing in a plain run.
- Every Loom run JVM carries `-XX:+ExitOnOutOfMemoryError` and the server GameTest run has an explicit `-Xmx` (`gradle/run-jvm.gradle.kts`, which also says when to re-measure it); `checkRunJvmOom` fails if either is dropped. The server GameTest run takes one of `DEEPCHARTER_SERVER_TEST_SLOTS` (default 2 on macOS) slots, a pool apart from the client slots (`gradle/clientlock.gradle.kts`). A server GameTest runs a body every tick with `TestTicks.each(helper, body)` (`test/support`, called from the test method, where it throws after tick 0), never `helper.onEachTick`, whose per-tick queue the runner keeps until the run ends (#548); the build fails on an `onEachTick` reference in `src/gametest`, and `tools/tests/each_tick_gate_check.py` tests the gate (run by `tools/tests/gate_checks.py`).
- A server GameTest writes a world clock (`setTotalTicks(`, `setPaused(`, `addTicks(`, `setRate(`) only through `TestClocks.paused` (`test/support`, restores in a `finally` on the same tick), or marks the line `// world-clock: <reason>`; the build fails otherwise, and client tests and evidence scenarios are exempt. The scan matches the method name, not the receiver: mark a non-clock `// world-clock: not a clock`. `tools/tests/world_clock_gate_check.py` tests this.
- A client test or evidence scenario hides or shows the HUD only through `ClientChecks.withHudHidden(context, body)` (or `withHudShown`; `withHudHidden(context, ParticleStatus, body)` also sets and restores the particle option), which restores the previous state in a `finally`, also when the body throws; every client test shares one client, so a leaked hidden HUD fails the next test that draws on it. The build fails on a `hud.toggle()`, `keyToggleGui`, `hideGui` or `KEY_F1` elsewhere in `src/gametest`; a deliberate toggle carries `// hud-toggle: <reason>` on its line or the one above. `HudHiddenClientTest` proves the restore, and `tools/tests/hud_toggle_gate_check.py` tests the gate (run by `tools/tests/gate_checks.py`).
- A test or scenario gets a layer's level, and turns a layer and a local Y into a world position, only through `TestLayers` (`test/support`: `level`, `isIn`, `dimension`, `worldY`, `pos`, `vec`); a literal world Y or `LayerChain.dimension(` elsewhere in `src/gametest` fails `checkFixedPosGate` (see [evidence.md](evidence.md)).
- A GameTest that cuts air into generated layer rock calls `RoomSeal.seal` first (generated lava and gas flood the cut otherwise).
- A tuning knob that counts blocks beyond a box says whether the edge cell is inside, and a test pins both sides (N in view, N+1 out).
- A new CHUNK_LOAD or other lifecycle listener needs a test that fires the real event or reloads a real chunk, not one that calls the handler directly.
- A change that lets any entity spawn naturally in a layer dimension pins `SPAWN_MOBS` false in every test and evidence world that enters that layer, via one shared setup (`test/support/TestPacks` sets it when each server starts).
- Run one client GameTest class with `./gradlew runClientGameTest -PclientTests=<filter>` or `tools/gametest.sh --client <filter>`. The filter is a comma-separated list of class names (simple or fully qualified) or globs (`Pod*ClientTest`; `*` matches any characters), matched against the client list that `generateGametestModJson` writes, and it also selects evidence scenarios. A term that matches no client class fails the build and names the term, so a typo never runs nothing and reports green. Without the property the list is the full one. The property is an input of the generation task, so changing it regenerates the list. A later plain `./gradlew build` or `runClientGameTest` regenerates the full list. `tools/tests/client_filter_gate_check.py` tests this, run by `tools/tests/gate_checks.py` (CI `build` job and pre-push hook).
- Run one GameTest, or a prefix of them, with `tools/gametest.sh '<test_id or prefix*>'` (quote the `*`). It runs `./gradlew runGameTest` from the repo root it lives in, sets the filter through `JAVA_TOOL_OPTIONS` (a bare `-D` on the Gradle command line is ignored), and fails when no test matches.
- `LavaBoreTest` (#231) is a measurement more than a regression test. By default it runs a 2-bore smoke case in seconds. `DEEPCHARTER_LAVA_BORES=<n> tools/gametest.sh 'lava_bore_test*'` runs <n> full bores of layer 1 (about 2.5 minutes for 100 on an 8-core M2) and prints `[lava-bore]` lines. `DEEPCHARTER_LAVA_BORES_LINING=<slabs>` makes the bot line (#313), and `DEEPCHARTER_LAVA_BORES_BRICKS=<n>` sets its starting bricks. `DEEPCHARTER_LAVA_BORES_LINER=<tier>` (#339) gives the pod a liner part of that tier instead and is measured alone: it is an error together with `_LINING`. `DEEPCHARTER_LAVA_BORES_PACK=<n>` puts that many bricks in a liner pilot's pack. The bot brakes in a fall; `DEEPCHARTER_LAVA_BORES_BRAKING=off` turns that off. `DEEPCHARTER_LAVA_BORES_BRACE=1` (#378) gives the pod the breach brace part. `DEEPCHARTER_LAVA_BORES_SHIELD=1` (#482) gives it the heat shield part (with a rack of `_BRICKS` and a pack of `_PACK`), and `DEEPCHARTER_LAVA_BORES_PILOT=leave|ignore` picks the pilot: `leave` climbs out of lava half a second after contact and turns back alive (lining by hand if it is trapped under rock), `ignore`, the default, never reacts; the run prints a `[lava-bore] summary:` line of the figures a design table reads. `DEEPCHARTER_LAVA_BORES_SOUNDER=<tier>` (#373) gives the pod the real seep sounder part of that tier (1 or 2); the bot then reacts only to what the part tells it (its HUD state and range) and steps aside from the pocket it shows, and the part bleeds what the bot drills into; it is an error together with a `_GAS` other than `ignore`. `DEEPCHARTER_LAVA_BORES_GAS=avoid` (#368) makes the bot step aside from a gas pocket that a tier 3 scanner (`ScannerTuning.gasTier`) would show in its next slab; `ignore`, the default, bores straight through; `sounder1` and `sounder` are design bounds, not counterplay the game has (the bot knows every pocket of its footprint in the 2 slabs below; `sounder` also knows the step's cells and tries all four sides). `DEEPCHARTER_LAVA_BORES_CHARGES=1` (#509) makes the bot set a blasting charge from the seat (the real item and use path) and hover clear of it, instead of sidestepping Company rock, and prints a `[lava-bore] charges` block; every run prints the `straight shafts` line. `DEEPCHARTER_LAVA_BORES_CONSOLE=<tier>` (#502) models the signal decay: the pod carries a console of that tier (0 is the stock one, still decayed; unset is no decay at all, as before), and the bot reads the plate (the sounder's line, the brace's prompt, the crust warning) and the scanner's window (the lava the lining bot looks for) only on ticks the decay leaves them readable; a Mole's cap makes 2 the top tier it can fit. `DEEPCHARTER_LAVA_BORES_HEED=1` makes a pilot without a brace turn back, alive, when the plate shows the crust warning. A decayed run prints a `[lava-bore] decay` line and a `decay depth` line. The cause tally is priority-ordered: lava, then gas, then charge, then landing, then crust. The numbers are in [mechanics.md](../../../docs/design/mechanics.md).
- `SurfaceCostTest` (#240) measures what the surface costs a new column of the tall world against the layers alone (ADR 0029 bar: 1.15x). By default it runs a smoke case: a few columns of each of the seven test worlds (`tall_baseline`, `tall_surface`, `tall_baseline_biomes`, `tall_surface_biomes`, and for the features of #245 `tall_surface_bare`, `tall_surface_yard`, `tall_surface_yard_bare`). `DEEPCHARTER_SURFACE_COST=<rounds> tools/gametest.sh 'surface_cost_test*'` measures 289 columns per world and round and prints `[surface-cost]` lines. `DEEPCHARTER_SURFACE_COST_ONLY=<world>` picks one of the seven worlds, so each heap reading is the first of its JVM. `tools/cost-run.sh <rounds> <world>...` (#473) measures worlds one JVM each, keeping the machine load beside each reading (limits and verdict in its header). A `bare` world is the same surface with every biome's features taken out, so the ratio of a world to its bare twin is what the features (stalks; the salvage crates in the yard worlds, which put every column in the yard) cost alone. The ratios and what they show are in [ADR 0036](../../../docs/adr/0036-the-surface-is-generated-from-data-by-a-replaced-overworld-dimension.md) and, for the features, [ADR 0047](../../../docs/adr/0047-the-surface-has-no-ore-the-bootstraps-metal-is-salvage-and-the-yard-is-a-biome.md). `SurfaceTerrainTest` runs in `deepcharter:surface_sample`, a copy of the shipped overworld in the test preset (the GameTest server bakes a flat overworld).
- `CampaignTerrainTest` (#742) runs in `deepcharter:campaign_sample`, the campaign world's test dimension (the game uses it from the cutover, #214): bands, rock, crust, zone biomes, and every data file's band edge against `test/support/CampaignBands`. Read a biome from the chunk's stored cell, never `level.getBiome` (it blurs a band edge). `CampaignContentTest` (#743) covers what the world holds besides terrain: structure sites, the Prospector wreck, the Conduit, cave stalks, figure spawns and every placed feature's height range against its band; the ore tables run in `OrePlacementTest` on both the layers and `campaign_sample`. `CampaignCostTest` measures it against two baselines with `test/support/ColumnCost` (shared with `SurfaceCostTest`): `tall_baseline` (vanilla stone, where the zone fill places nothing; the strict comparison #742 used, and the one the bar is judged on) and `tall_layer` (the layer's own rock, so the fill works in every row; context only, because the fill covers 2048 of its 2048 rows but only the layers' rows of the campaign world, and the test prints both counts). `DEEPCHARTER_CAMPAIGN_COST=<at least 4> tools/gametest.sh 'campaign_cost_test*'` fails over 1.15x CPU per block of height on the medians against `tall_baseline`; `DEEPCHARTER_CAMPAIGN_COST_ONLY=<world[,world]>` picks worlds (`tools/cost-run.sh` reads `[surface-cost]` lines only, so it does not run this test). Read the per-round pairs: readings drift upward on a loaded Mac.
- Every mod screen must fit the default window (854 x 480, GUI scale 2). `ScreenLayoutClientTest` (#381) opens each screen with its largest content and fails, naming the screen, the widget and the overflow in pixels, when a widget leaves the screen or two interactive widgets overlap. It finds terminal screens through `TerminalTypes.all()` and `TerminalScreens.create`, and container screens through the registered menu types; a new terminal feature or menu type needs a fixture there, or the test says so. A screen that scrolls declares its region with `Case.scrolls`. A screen nothing registers is a case in `standalone()`, and `tools/tests/test_screen_layout_gate.py` fails on one that is not. It also renders each screen once through a recording `GuiGraphicsExtractor` (`test/support/DrawnText`, #411) and fails, naming the screen, the string and the overflow in pixels, when text the screen draws itself (`graphics.text`, `CrtDraw.glowText`) leaves the screen or a declared scroll region, or overlaps an interactive widget; text drawn inside a widget's own render is the widget's and is skipped, and the typewriters are finished first. `textWithWordWrap` is not recorded. A screen draws text only inside its own extract method or inside a widget; `addRenderableOnly` and custom `Renderable`s are refused, because the drawn-text gate skips text under any non-Screen `Renderable`. The Python gate takes the transitive closure of screen classes (`extends PanelBase` counts) and fails on a `setScreen(make())` factory not listed in `FACTORIES`. Keep a per-screen layout test only for what this one does not check.
- A gate that matches source text must match inside the declaration it guards, never a bare mention.
- A non-private member of `src/main` or `src/client` that only `src/gametest` references fails `checkTestOnlyMembers` (part of `check`): delete it and test through the seam production uses, or make it private. A deliberate, permanent seam carries `// test-seam: <why it is deliberate>` on its declaration line or the comment line above. A `static final` field of a registered game object (Block, Item, EntityType and the like) and an abstract method are exempt.
- Before you drive an entity in a far chunk, await entity ticking: `test/support/FarChunks.awaitEntityTicking`. It forces the chunk, so nothing else needs to keep it loaded, and `GameTestInfoMixin` lets it go when the test finishes (#569). The force-chunk gate (`gradle/gametest.gradle.kts`, part of `generateGametestModJson`) fails any `setChunkForced`, `updateChunkForced` or forced ticket in `src/gametest` outside `FarChunks`. A test never forces or releases a chunk directly: force with `FarChunks.force(helper, level, x, z)` (or `awaitEntityTicking`), release early with `FarChunks.release(helper, level, x, z)`, and pin the colony pad with `FarChunks.pin`. A case with no `GameTestHelper` (a client test, an evidence scenario) is marked `// force-ok: <reason>`. A chunk left forced pins up to 17 x 17 chunks of proto chunks for the rest of the run, which is what filled the heap.
- In a client GameTest or evidence scenario, wait with `test/support/ClientWait.until` (or `ClientWait.screen` for a screen), never `context.waitFor` or `waitForScreen`. The client and server tick unthrottled, so a tick budget is a different wall time under load. `until` polls a 120 s wall-clock deadline and its failure names what it awaited and what the client had. The build fails on a `waitFor` in a client test, in the client test support or in `test/evidence/`; a deliberate fixed-tick wait carries `// tick-wait: <reason>` on its line or the one above. `tools/tests/tick_wait_gate_check.py` tests this, run by `tools/tests/gate_checks.py` (CI `build` job and pre-push hook).
- A world load (`worldBuilder().create()`, `TestDedicatedServerContext.connect()`) is waited on by `test/support/WorldLoadWait`, a 300 s wall-clock deadline whose failure names the stage (connect and login, or world load) and what the client had. Fabric's own wait, `ClientGameTestImpl.waitForWorldLoad` (1200 ticks, "Timeout loading world"), is replaced by `test/mixin/ClientGameTestImplMixin`, a test-only mixin in the gametest mod. `WorldLoadWaitClientTest` fails if a load does not reach it. If a Fabric update breaks the mixin, the client launch fails; fix the target, do not remove the mixin.
- Each client test class has a 180 s wall-clock limit (#434): `ClientTestLog.start(this)` arms `test/support/ClientTestWatchdog`; `startUntimed(this)` is for a class that is long by design (the evidence scenarios). `DEEPCHARTER_CLIENT_TEST_SECONDS=<n>` changes the limit (`0` turns it off). Past the limit the run logs `CLIENT-GAMETEST TIMEOUT <class>` with every thread's stack and exits 1. `WatchdogHangClientTest` hangs on purpose under `DEEPCHARTER_HANG_FIXTURE=1`. Diagnosis: #434.
- `test/support/MockPlayers` joins a real server-side player with no client behind it. It cannot receive packets: test payload builders directly.
- The runner keeps every finished `GameTestInfo` for the whole run, so a callback still pending when a test ends (the next-tick entry of `TestTicks.each`) kept its mock `ServerPlayer` and its `PlayerAdvancements` alive; `GameTestTickerMixin` now clears every done test's pending callbacks and sequences, however it finished (#656). `MockPlayersTest.finishedTestDoesNotRetainItsMock` guards it.
- A level's `EntityTickList` keeps its `passive` map, a snapshot of every entity ticking at its last change made during an iteration, so a removed player stays on the heap until another such change; `MockPlayers` empties it at the end of a tick in which a mock left (`TickLists`, #723).
- A mock's `leave()` disconnects its `Connection`, not just `player()`: a respawn swaps the `ServerPlayer` under the same listener, and Fabric ends its networking addon (which its registry holds) only on that disconnect. Respawn a mock with `connection.handleClientCommand(PERFORM_RESPAWN)`, not `PlayerList.respawn` (it leaves the listener on the dead player). A Fabric event cannot be unregistered, so a listener a test registers captures ids and plain values, never a `MockPlayer` or `ServerPlayer` (#698).
- Pod movement ignores `Entity.setNoGravity` (#554): hold a pod still with a `PodEvents.AFTER_TICK` pin (see `TwoPlayerClientTest`).
- Swap a world-global record only through `WorldData` (a gate enforces it; `WorldDataGuard` watches only the dedicated GameTest server). Read loaded chunks through `scanner/LoadedBlocks`.
- A printf-style helper in gametest needs `@FormatMethod`/`@FormatString` (`AnnotateFormatMethod` is on).
- `-PclientTests=<server test class>` fails the build, and `-PclientTests` never runs evidence scenarios (use `tools/record-evidence.sh <scenario>`). A client-GameTest failure on CI uploads `build/run/clientGameTest/screenshots` (`gh run download <id>`).
- Scan the world in tests and scenarios through `test/support/BlockSurvey`.
- Before you write a new bore bot (a pilot's `Input`s, a sidestep `Side`, a lining check) or a scenario camera helper (a structure-axis `at`), look in `test/support` (`BoreBot`) and `EvidenceScenario` and in the nearest sibling test or scenario, and extract there if a second copy would appear.
- A client test that wants its own pod never uses `getEntities(POD).getFirst()`; the colony's wreck pod shares the level. Select by tag, UUID or position.
- `test/support/TwoPlayerServer` starts a dedicated server in a client GameTest, joins the real client, then joins one mock player.
- Wait on entity ticks, not server ticks: chunks far from the players do not tick at first in a fresh world.
- A server GameTest that waits for generated blocks polls under `FarChunks.Deadline`, snapshots chunk state (without loading) before reading blocks, and logs when the wait was needed.
- A test that runs git in a temp repo clears every `GIT_*` variable and sets `cwd` and `GIT_CEILING_DIRECTORIES`; the pre-push hook also unsets them before running tests.
- `ScannerFrameTimeClientTest` (#537) is a measurement, not a regression guard and not a pass line (it asserts only that the panel is drawn): it logs `[scanner-frame]` lines, the CPU milliseconds of one frame's render-state extraction (the HUD with its scanner panel) at the top scanner tier on a full-rock area, with no scanner, with one, and with the HUD hidden as a control. It unpaces the client (no vsync, no frame limit) and restores both. Do not time a client tick (it waits for the 20 ticks a second) or `renderFrame` (it returns at once in a test, drawing nothing).
- A visual-legibility test measures at the on-screen cell size of the smallest shipped window, not at the unscaled tile.
- A test that restates a registry (a hand-copied list of names) is not a test; read the registry.
- A render-path feature with its own update loop (`FloodlightBeams`) needs a client GameTest driving it, not only an evidence scenario.
- A change to shared client visuals runs every client test class that reads them, not only its own (#630 missed `TextureLayersClientTest`).
- Prove a regression test with a mutation check: break the code under test in your worktree, see it go red, revert (#627's first case was vacuous).

## Client slots

On macOS at most two game clients run at a time (`DEEPCHARTER_CLIENT_SLOTS`, default 2; `1` allows one). `runClient`, `runPlay` and `runClientGameTest` (so also `tools/play.sh` and `tools/record-evidence.sh`) take a machine-wide slot, a lock file in `~/.cache/deepcharter/` (`client.lock` is slot 0). A run that finds both slots taken prints `Waiting for a game client slot (queue position <n> of <m>). Slot 0: <worktree> ... PID <n>; Slot 1: ...` and is served in arrival order. Do not check `pgrep` first. The OS frees a slot when its holder exits or dies, and a waiter that dies leaves a ticket that the others skip, so Ctrl-C and crashes need no cleanup. `tools/play.sh` and `tools/record-evidence.sh` run Gradle with `--no-daemon`, so Ctrl-C of a waiting run ends it. For a direct `./gradlew runClientGameTest`, a Ctrl-C while the run waits leaves the Gradle daemon polling, and it would take a slot with no one watching. After such a Ctrl-C, run `./gradlew --stop` in that worktree. [gradle/clientlock.gradle.kts](../../../gradle/clientlock.gradle.kts) holds the details.
