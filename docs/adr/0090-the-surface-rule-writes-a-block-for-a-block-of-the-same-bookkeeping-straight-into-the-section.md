# The surface rule writes a block for a block of the same bookkeeping straight into the section

Issue [#1160](https://github.com/pkeppeler/deepcharter/issues/1160), part of [#1132](https://github.com/pkeppeler/deepcharter/issues/1132); the cost gate is [ADR 0086](0086-each-campaign-band-is-held-to-one-layers-cost-per-row-and-the-whole-worlds-ratio-is-only-tracked.md).

## Decision

- **The target.** `net.minecraft.world.level.levelgen.material.MaterialSystem$1`, the anonymous `BlockColumn` that `MaterialSystem.buildSurface` hands the surface rule, method `setBlock(ILnet/minecraft/world/level/block/state/BlockState;)V` (checked against the 26.3 jar). `surface/mixin/MaterialSystemBlockColumnMixin` redirects its one call to `ChunkAccess.setBlockState(BlockPos, BlockState)` into `surface/SurfaceWrites.set`. `require` is 1 through `defaultRequire`, so a rename fails the load.
- **The fast path.** `SurfaceWrites.set` writes `LevelChunkSection.setBlockState(x, y, z, state, false)` and skips the rest of `ProtoChunk.setBlockState` when all of these hold, and otherwise calls vanilla unchanged:
  - the chunk is exactly a `ProtoChunk` (not `ImposterProtoChunk`, which wraps a live `LevelChunk`) whose status is before `INITIALIZE_LIGHT`: the surface step of generation, never a live-world write;
  - neither the old nor the new state is air;
  - neither has a block entity, nor a fluid;
  - `LightEngine.hasDifferentLightProperties(old, new)` is false (dampening, emission, shape occlusion);
  - for every `Heightmap.Types`, `isOpaque` gives the same answer for both states.
- **Why those are all of it.** In 26.3 `ProtoChunk.setBlockState` writes the section, then (a) from `INITIALIZE_LIGHT` on, updates the light engine when the section's only-air flag flips and when the light properties differ, and (b) calls `Heightmap.update` on each heightmap the status keeps. It marks no post-processing, touches no block entity and keeps no light-source list. The caller `MaterialSystem$1.setBlock` marks a position for post-processing when the new state has a fluid. Non-air to non-air cannot flip the only-air flag; the status check and the light test make (a) a no-op; `Heightmap.update` reads the new state's predicate and, only on a rescan, the chunk's blocks, so with equal predicates on a heightmap that matches the blocks it changes nothing, and a heightmap not yet primed is primed from the blocks later, with the same result. Every predicate is compared by calling it, not by listing what it tests, so a type's change in a Minecraft update is covered. The section's block, tick and fluid counts are kept by `LevelChunkSection.setBlockState` itself, which both paths call.
- **The lock.** The 26.3 path is `LevelChunkSection.setBlockState(x, y, z, state, false)` to `PalettedContainer.getAndSetUnchecked`, which skips the `acquire`/`release` of the container's `ThreadingDetector` that `getAndSet` takes. The detector crashes when two threads touch a container together, so it excludes nothing a single thread needs; it is also a diagnostic, and the fast path deliberately stops reporting there. During the surface step the chunk is generated by one chunk-generation task, and the rule writes only the chunk it is building (`MaterialSystem$1` holds that one `ProtoChunk` and a column inside its bounds). `NoiseBasedChunkGenerator.doFill` writes the same sections in the previous step by the same unchecked call. On a version bump, `SurfaceWritesTest`'s random-write comparison of the two paths is the drift guard for what `ProtoChunk.setBlockState` does.
- **A one-pair cache.** The heightmap predicates test tags (a hash lookup each), and judging a pair cost more than the lock it saves (the first version read layer 1 slower, 1.37x against 1.12x with the path off). `SurfaceWrites` keeps the last pair judged; a column writes one pair row after row. The pair is stored with a tag-reload generation (`CommonLifecycleEvents.TAGS_LOADED` bumps it), and a stored verdict of another generation is a miss, even one a worker judged before the reload and stored after it.
- **A switch.** `-Ddeepcharter.fastSurfaceWrites=false` turns the fast path off (read once at class load), for the cost measurement and as a bisect lever. `SurfaceWritesTest` flips it in code (`setEnabled`, restored in a `finally`) to generate a chunk the vanilla way, and counts the fast writes of one watched chunk position (`watch`, `watchedWrites`) to prove the mixin is on a real chunk's writes; the live and lit cases assert on `fastSection`, which holds the whole guard.

## Why

- Layer 1's band sits in a campaign whose `default_block` is `green_shale`, so the rule rewrites every solid row to `packed_shale`: about 159 writes a column, against 3 in `tall_layer` and layer 2. Profiled, the lock and the heightmap and chunk bookkeeping of each write are a large part of layer 1's excess (#1132).

## Rejected

- **Change the campaign's `default_block` to `packed_shale`.** Layer 2 then rewrites every row instead, and moves the cost without cutting it.
- **A surface rule that skips a row already holding the target.** The rule language has no such test, and the rewrite is a different block (`green_shale` to `packed_shale`).
- **Write the section for every surface write.** A write that changes a heightmap, light or a fluid needs vanilla's bookkeeping; a guard that falls back keeps the world identical by construction.

## Consequences

- Layer 1's ratchet in `CampaignCostTest` is deleted (it measures under the 1.15x bar). Layer 2 does not use the path and keeps its ratchet. Measurements are in the PR. If layer 1 flakes over the bar on a CI VM, re-measure; do not restore the ratchet.
- The world is byte-identical: `CampaignWorldHashTest` gives the same lines (blocks, biomes, heightmaps) with the switch on and off; `SurfaceWritesTest` compares both paths on the same writes.
- A Minecraft update that adds a side effect to `ProtoChunk.setBlockState` is not seen by the guard. The mixin's target is the only thing that fails loudly; re-read `ProtoChunk.setBlockState` when the version moves.

## Amended

2026-11-25, [#1277](https://github.com/pkeppeler/deepcharter/issues/1277): the one-pair cache is now a table of every pair judged, shared by the worker threads and replaced whole when a pair is added (`SurfaceWrites.known`, at most 64). Layer 1's strata make a column write a few pairs in turn, and the worker threads each write their own chunk's, so one last pair shared by every thread missed on most writes: layer 1's window cost about 1.4 times as much with three rocks as with one (numbers in the PR).

2026-11-26, [#1472](https://github.com/pkeppeler/deepcharter/issues/1472): layer 1's strata (#1277) made the rewrite of every solid row cost layer 1 about 0.15x of the bar again, so the noise fill now writes the strata's rock in advance and the rewrite finds it there.

- **The target.** `layer/mixin/NoiseBasedChunkGeneratorMixin` on `NoiseBasedChunkGenerator.doFill(NoiseChunk, ChunkAccess)` (checked against the 26.3 jar): at its head it works out the generator's `layer/gen/StrataPrefill`, and it redirects its one call to `Aquifer.computeSubstance(IIID)`, whose null is a solid block that takes the default block. Where the substance is null and the row is in layer 1, it returns the prefill's block for the row; elsewhere it returns the substance. Only a generator of the `deepcharter:campaign` settings whose material rule holds a `deepcharter:strata` rule prefills.
- **The guess.** The strata's rock with unmoved contacts (`StrataRule.rockAt(y, 0)`). The material rule writes a block over every solid block of layer 1 (the strata, and the breach crust under them), so the fill's block never reaches the world. The rule's conditions read no block, the stone depth reads only solid or not, and every rock of the guess is as solid and opaque as the default, so the heightmaps are the same. A wrong guess (a row near a moved contact, the crust) is rewritten as before.
- **The skip.** `SurfaceWrites.set` returns without writing when the neutral write's block is already there: writing a block over itself changes no section, count, heightmap or light.
- **The proof.** `StrataPrefillTest` compares a chunk of `campaign_full` (prefilled) with the same chunk of `campaign_sample` (its own settings, never prefilled) over layer 1 and the rows next to it, and counts the skipped writes; `CampaignWorldHashTest` gives the same lines as `origin/main` (numbers in the PR).
